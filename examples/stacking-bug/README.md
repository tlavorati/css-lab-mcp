# Example: dropdown trapped in a card's stacking context

A feed of cards uses a broad rule:

```css
.card > * {
  position: relative;
  z-index: 1;
}
```

Every direct child of every card becomes its own stacking context with `z-index: 1`.
The dropdown menu inside card #1 has `z-index: 1000`, but that value only counts *inside*
card #1's header. At page level, card #1's header and card #2's header are both `z-index: 1`,
so DOM order decides and card #2 paints on top. Clicking "Delete" in the open menu hits card #2.

Raising the menu to `z-index: 9999` does nothing. The fix is to raise the card child that
contains the open menu:

```css
.card > .card-header:has(.menu.open) {
  z-index: 2;
}
```

## Try it

```bash
# Before: exit code 2, verdict COVERED_BY_SIBLING_STACKING_CONTEXT
npx -p css-lab-mcp css-lab inspect examples/stacking-bug/before.html \
  --selector ".card:nth-child(1) .menu-item.danger" \
  --pre "click:.card:nth-child(1) .menu-toggle" --pre "wait:.menu.open"

# After: exit code 0, verdict OK
npx -p css-lab-mcp css-lab inspect examples/stacking-bug/after.html \
  --selector ".card:nth-child(1) .menu-item.danger" \
  --pre "click:.card:nth-child(1) .menu-toggle" --pre "wait:.menu.open"
```

From a clone of this repository, use `node dist/cli.js` instead of `npx -p css-lab-mcp css-lab`
(after `npm run build`).
